# PHISHintoASH — AI-Powered Phishing URL and Email Detector

An educational cybersecurity portfolio project for an IBM SkillsBuild Cybersecurity submission. It combines transparent URL features, message heuristics, and a TF-IDF plus Multinomial Naive Bayes text classifier in a Streamlit dashboard.

## Project layout

```text
phishing-url-email-detector/
├── app.py                 # Streamlit user interface
├── detector.py            # URL features, heuristics, combined scoring
├── model_trainer.py       # Train/evaluate synthetic demo classifier
├── requirements.txt       # Runtime dependencies
├── README.md              # Setup, design, and usage
├── PROJECT_REPORT.md      # Submission-ready project report
└── message_model.joblib   # Generated by model_trainer.py
```

## Architecture and threat model

Input is treated as untrusted text. The detector checks URL characteristics: length, `@`, IP hosts, many subdomains, hyphens, selected TLDs, unusual ports, lack of HTTPS, and credential-related words. For message text, it checks urgency, suspicious actions, and brand/account language, then optionally scores text with TF-IDF and Naive Bayes. The interface combines these signals into an explainable 0–100 risk estimate and reports triggered indicators.

The threat model is credential theft and social engineering delivered through links or messages. The tool does not fetch links, inspect attachments, validate sender identity, or guarantee detection. HTTPS does not establish that a site is trustworthy. A benign score is not proof of safety, and an alert requires human review.

## Setup and run

Use Python 3.10 or newer.

```bash
python -m venv .venv
# Windows PowerShell
.venv\Scripts\Activate.ps1
# macOS/Linux: source .venv/bin/activate
python -m pip install -r requirements.txt
python model_trainer.py
streamlit run app.py
```

The trainer saves `message_model.joblib` beside the scripts and prints holdout accuracy and a confusion matrix. Included data is tiny and synthetic; those metrics demonstrate the workflow only. For credible evaluation, use a larger, current, appropriately licensed labeled dataset, deduplicate it, and evaluate on a temporally and source-separated test set. For custom data, load a CSV with `text` and binary `label` columns (`0` legitimate, `1` phishing), then call `train(data)` from `model_trainer.py`.

## Sample inputs

**Benign message**
```text
Your library book is due next Tuesday. Renew it online if needed.
```

**Suspicious message**
```text
Immediate action required: verify your account now to avoid suspension. Click here to sign in.
```

**Suspicious URL**
```text
http://secure-account-help.xyz/verify/login
```

## Scoring and limitations

Classification thresholds are `Legitimate` below 35, `Suspicious` from 35 through 69.9, and `High-Risk Phishing` at 70 or above. Scores are hand-weighted signals, not calibrated probabilities. The synthetic training set cannot represent real phishing diversity. False positives and false negatives are expected. Do not enter secrets or rely on this tool as the sole security control.

## Responsible use

Use only for education, defensive analysis, and authorized testing. Avoid opening suspicious links. Check suspected messages through a known-good contact method and report them through approved channels.

## Contact and feedback

The dashboard's **Contact me by email** link opens a Gmail draft addressed to the `contact_email` value in Streamlit secrets. The feedback form sends feedback to that address when SMTP is configured. All contact and SMTP credentials belong in `.streamlit/secrets.toml`, which is excluded from Git. Never put an email address or password in `app.py` or commit your real secrets file.

To configure contact, copy `.streamlit/secrets.toml.example` to `.streamlit/secrets.toml` and set `contact_email` to your private destination address. To enable automatic feedback delivery, also enter SMTP settings for an email account you control. For Gmail, use an app password if your account supports it; do not use your normal account password. Restart Streamlit after adding the file. If SMTP is not configured, the form opens a prefilled Gmail compose page as a fallback; the visitor must review and send it.
